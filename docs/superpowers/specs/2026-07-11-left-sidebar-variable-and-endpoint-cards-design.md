# 左侧栏变量选择与端点分组卡片设计

## 目标

将应用左侧栏分为上下两区：顶部以按钮单选方式展示 `config.json` 的 `variables`，底部以按 `endpoint_groups` 分组的卡片展示 `endpoints`。变量选择会立即影响当前请求的变量替换结果。

## 范围

本次仅调整前端左侧栏与前端配置状态：不改变 `config.json` 格式、Go 后端接口或配置写入行为。

## 交互与布局

### 变量选择区

- 位于左侧栏最上方，显示所有 `config.variables` 项。
- 每个变量以按钮显示：优先展示 `environment`，同时保留 `id` 以便区分同名环境。
- 变量为全局单选；首次载入配置时默认选择数组第一项。
- 用户切换变量后，配置 store 的当前变量更新；当前已打开的请求按新变量的 `base_url` 立即重新计算 URL。
- 当没有变量时，该区显示空状态，且既有请求不做替换。

### 端点卡片区

- 位于变量选择区下方，保留搜索、HTTP 方法筛选、折叠分组、端点禁用和端点选中行为。
- 每个 `endpoint_group` 渲染为独立卡片，标题显示组名，组内列出该组端点。
- 分组从预设的可访问颜色序列中按配置顺序稳定分配强调色；该色用于卡片边框、标题标记和组内端点的轻量视觉提示。
- 同一分组内端点使用该组颜色，当前选中状态仍使用高对比度的全局选中样式。
- 无 `group_id` 的端点显示为“未分组”卡片，并使用中性色。
- 空筛选结果显示明确的空状态。

## 状态与数据流

1. `configStore.loadConfig()` 取得配置后，初始化或校正当前变量 ID。
2. `selectedVariable` 从当前变量 ID 和 `config.variables` 计算得到。
3. `substituteVariables()` 使用已选变量的值替换对应占位符；选择变量时，若当前端点存在，则重新载入该端点请求内容以刷新 URL。
4. 选择端点时，请求编辑器同样使用当前变量值加载 URL。
5. `EndpointList` 根据 `endpointGroups`、筛选后的端点和稳定颜色映射渲染卡片。

## 错误处理与边界

- 配置重载后，若原选变量不存在，回退至第一项；没有变量则清空选择。
- 变量缺少 `environment` 时，只显示 `id`。
- 端点引用未知分组时，视作未分组，避免端点丢失。
- 禁用端点不可选择；搜索和方法筛选不改变配置或全局变量选择。

## 测试

- 为配置 store 添加/扩展单元测试：默认变量、变量切换后的替换、配置重载时的选择回退。
- 为左栏组件添加组件测试（若项目测试工具可用）：变量按钮单选、切换后刷新当前请求、分组卡片颜色和未分组回退。
- 运行 Go 测试与前端类型检查/构建，确保现有功能未回归。
