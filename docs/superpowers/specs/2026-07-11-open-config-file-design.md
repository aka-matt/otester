# 运行时加载配置文件设计

## 目标

将 File 菜单中的“Open Config Directory”替换为“Open Config File”，让用户通过系统文件选择器载入新的 JSON 配置文件。

## 行为

- 选择文件后，后端解析并验证该文件；成功时将它设为本次运行的活动配置并返回脱敏后的 `ConfigView`。
- 用户取消选择时不改变当前配置。
- 无法读取、JSON 解析失败或配置校验失败时，保留原活动配置，前端显示错误。
- 成功后前端刷新配置状态、按现有规则保留或回退变量选择，并清空当前响应。
- Reload Config 重读当前活动配置文件。
- 活动路径只存在后端内存中；重启应用后恢复读取当前工作目录的 `config.json`。

## 架构

- `internal/config` 提供按明确路径加载的函数，只有解析成功后才更新 `currentConfig`。
- `app.App` 持有运行时活动配置路径。启动时初始化为工作目录 `config.json`，文件选择完成后只在成功加载时替换该路径。
- `App.OpenConfigFile` 使用 Wails runtime 的原生文件选择对话框，限制为 JSON 文件，返回取消或加载错误。
- 前端菜单调用新方法，并在成功时把返回的配置放入 Pinia store；旧的打开目录接口和菜单项移除。

## 测试

- 配置加载器测试成功加载指定路径、失败时保留现有配置。
- App 层测试以可注入选择结果或路径加载逻辑覆盖成功替换、取消不变和失败不变。
- 前端测试菜单的新标签和成功/失败处理；运行 Go 测试及前端测试/构建。
