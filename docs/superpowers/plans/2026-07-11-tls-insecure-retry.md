# TLS Insecure Retry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When `config.json` has `allow_insecure_tls: true`, a request to a server with a problematic TLS certificate (expired, self-signed, hostname mismatch, untrusted CA, …) still completes and the Certificate tab surfaces the original validation error alongside the server's certificate chain.

**Architecture:** Backend retry — `httpclient.DoRequest` tries the request with the normal shared client; if `Do` returns an error matching `tls:` or `x509:` AND the client has been told `allow_insecure_tls: true`, it retries once with a per-call `http.Client` whose `Transport.TLSClientConfig` is `&tls.Config{InsecureSkipVerify: true}`. On retry success, the returned `TLSInfo` carries the cert chain from the retry plus two new fields — `ValidationSkipped=true` and `OriginalError=<first attempt message>`. Status stays `"ok"`; the two new fields distinguish clean from insecure-retry success. The retry uses a fresh client per attempt (no mutation of the shared transport). App-level plumbing tracks the flag on the `App` and pushes it into the `httpclient.Client` via a setter on every config load.

**Tech Stack:** Go stdlib (`crypto/tls`, `crypto/x509`, `net/http`, `sync`), Vue 3, TypeScript, Naive UI.

## Global Constraints

- Use only Go stdlib for TLS parsing — no third-party libraries.
- Status taxonomy stays `"ok"`, `"handshake_failed"`, `"no_tls_attempted"`. Add NO new status value. `"ok"` is reused for the retry-succeeded path.
- The retry uses a freshly constructed `http.Client` per attempt; do NOT mutate the shared client's transport mid-flight.
- TLS handshake failure detection: error string contains `"tls:"` or `"x509:"` AND is not a context timeout/cancel — same logic as `BuildTLSInfoFromError`.
- A config reload (`LoadConfig` / `OpenConfigFile` / `ReloadConfig`) updates the flag without restarting the app.
- Frontend prop is `info: TLSInfo | null`. Boundary uses `response.tls ?? null`.
- `TLSInfo.ValidationSkipped` defaults to `false`; `OriginalError` defaults to `""`. The frontend banner is rendered only when both conditions hold (status === `"ok"` AND `validationSkipped === true`).
- All new Go code follows stdlib idioms; no new dependencies in `go.mod` / `frontend/package.json`.
- All new tests follow TDD: failing test first, then minimal impl, then verify pass.
- Commit after each task with a `feat:` or `test:` message.

```go
// When resp.TLS is nil (plain HTTP), status is "no_tls_attempted".
// When validationSkipped is true (the request succeeded via a retry with
// InsecureSkipVerify after a first attempt failed), the returned TLSInfo
// carries ValidationSkipped=true and OriginalError=<first attempt message>.
func BuildTLSInfo(resp *http.Response, req *http.Request, validationSkipped bool, originalError string) *model.TLSInfo {
	host := ""
	if req != nil && req.URL != nil {
		host = req.URL.Host

	if resp.TLS == nil {
		return &model.TLSInfo{

			TargetHost: host,
		}

	return &model.TLSInfo{
		Status:              "ok",
		TargetHost:          host,
		AttemptedServerName: resp.TLS.ServerName,
		Connection:          buildConnectionView(resp.TLS),
```

```go
// InsecureTLSClient returns a fresh *http.Client whose Transport skips
// certificate validation. It is intended for one-shot retry attempts
// after a TLS handshake failure; the returned client must not be shared
// across goroutines because each call constructs a new Transport.
func InsecureTLSClient() *http.Client {
	return &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{InsecureSkipVerify: true},

}
```

```go
type Client struct {
	client           *http.Client
	cancelFuncs      map[string]context.CancelFunc
	mu               sync.RWMutex
	allowInsecureTLS bool
}

func NewClient() *Client {
	return &Client{
		client: &http.Client{
			Timeout: 30 * time.Second,
		},
		cancelFuncs: make(map[string]context.CancelFunc),
	}
}

// SetAllowInsecureTLS toggles the fallback behaviour: when a TLS handshake
// fails because of certificate validation, the next request will be retried
// once with InsecureSkipVerify=true. The flag is read on every DoRequest call,
// so callers can flip it at runtime without restarting the client.
func (c *Client) SetAllowInsecureTLS(enabled bool) {
	c.mu.Lock()
	c.allowInsecureTLS = enabled
	c.mu.Unlock()
}

func (c *Client) getAllowInsecureTLS() bool {
	c.mu.RLock()
	defer c.mu.RUnlock()
	return c.allowInsecureTLS
}
```

- [ ] **Step 4: Add the retry logic in `DoRequest`**

Replace the body of `DoRequest` in `internal/httpclient/client.go`. The new flow:

1. Try the request with `c.client`.
2. On error, classify: is it a TLS error (`tls:` or `x509:` in the message) AND is the insecure flag on? If both true, retry with `InsecureTLSClient()`.
3. On retry success → return `ParseResponse` result with `BuildTLSInfo(resp, req, true, firstErr.Error())`.
4. On retry failure → fall back to `handleRequestError` using the second error.
5. On first-attempt error with no retry → existing `handleRequestError` path.

```go
func (c *Client) DoRequest(ctx context.Context, input *model.RequestInput) (*model.ResponseOutput, error) {
	reqCtx, cancel := context.WithTimeout(ctx, time.Duration(input.TimeoutSeconds)*time.Second)
	defer cancel()

	c.mu.Lock()
	c.cancelFuncs[input.RequestID] = cancel
	c.mu.Unlock()

	defer func() {
		c.mu.Lock()
		delete(c.cancelFuncs, input.RequestID)
		c.mu.Unlock()
	}()

	req, err := BuildRequest(reqCtx, input)
	if err != nil {
		return &model.ResponseOutput{
			RequestID:    input.RequestID,
			ErrorCode:    string(model.ErrInvalidURL),
			ErrorMessage: err.Error(),
		}, nil
	}

	start := time.Now()
	resp, err := c.client.Do(req)
	duration := time.Since(start)

	if err == nil {
		defer resp.Body.Close()
		return ParseResponse(resp, req, input.RequestID, duration)
	}

	// First attempt failed. Classify: is this a TLS error and is the insecure flag on?
	if c.getAllowInsecureTLS() && isTLSError(err) {
		retryClient := InsecureTLSClient()
		retryStart := time.Now()
		retryResp, retryErr := retryClient.Do(req.Clone(reqCtx))
		retryDuration := time.Since(retryStart)

		if retryErr == nil {
			defer retryResp.Body.Close()
			totalDuration := duration + retryDuration
			output, parseErr := ParseResponse(retryResp, req, input.RequestID, totalDuration)
			if parseErr != nil {
				return nil, parseErr
			}
			if output.TLS != nil {
				output.TLS.ValidationSkipped = true
				output.TLS.OriginalError = err.Error()
			}
			return output, nil
		}

		// Retry also failed — fall through to handleRequestError with the second error.
		return handleRequestError(input.RequestID, reqCtx.Err(), retryErr, duration+retryDuration, req)
	}

	return handleRequestError(input.RequestID, reqCtx.Err(), err, duration, req)
}

// isTLSError returns true when err's message contains "tls:" or "x509:",
// matching the same heuristic as BuildTLSInfoFromError.
func isTLSError(err error) bool {
	if err == nil {
		return false
	}
	msg := err.Error()
	return strings.Contains(msg, "tls:") || strings.Contains(msg, "x509:")
}
```
